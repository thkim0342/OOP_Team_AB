# 서울시 버스정류장·생활인구 데이터 전처리

파트 1의 A·B가 `DataLoader` 클래스를 함께 개발하는 저장소입니다. 저장소에 포함한 버스정류장 CSV, 자치구별 생활인구 CSV, 자치구 경계 파일을 읽고 정제하여 다른 클래스에서 사용할 데이터를 제공합니다.

팀원 모두 같은 원본 파일을 사용하며 데이터 갱신은 파일 교체로 진행합니다. 인구 데이터는 **생활인구**를 사용합니다.

## A·B 역할과 작업 범위

| 담당자 | 담당 메서드 | 책임 |
| --- | --- | --- |
| A — 데이터 파이프라인 | `load_data()` | 원본 파일 확보·공유, 경로·인코딩 처리, CSV·공간 파일 읽기, 필수 컬럼 확인, 표준 컬럼명 적용, 출처·기준시점 기록 |
| B — 데이터 정제 및 병합 | `clean_data()`, `merge_data()` | 자료형·결측·중복 처리, 분석 대상 구분, 좌표계 통일, 정류장의 자치구 매핑, 생활인구와 자치구 연결, 처리 결과 검증 |

A·B의 완료 지점은 **정류장·생활인구·자치구 경계가 공통 코드로 연결된 데이터 묶음을 제공하는 것**입니다.

### 다른 파트와의 책임 경계

아래 내용은 데이터 전달 경계를 정하기 위한 설명입니다.

| 작업 | A·B의 범위 | 후속 담당자의 범위 |
| --- | --- | --- |
| 정류장·자치구 객체 | 객체 생성에 필요한 필드와 자료형 제공 | C가 `BusStop`, `District` 정의 및 객체 생성·기본 정보 관리 |
| 정류장 소속 구 판별 | B가 전처리 과정에서 `district_code`를 배정 | C가 판별 규칙·경계 사례 검토를 지원하고 결과를 객체에 반영 |
| 면적 | A가 면적 자료를 확보하고 B가 단위를 km²로 정리. 필요하면 경계 도형에서 계산 | C가 `District`의 면적 속성으로 관리 |
| 정류장 수·분석 지표 | 정류장 목록, 생활인구, 면적 등 입력값 제공 | C·D가 소속 정류장 집계 및 밀도·생활인구 대비 지표·형평성 점수 계산 |
| 지도·차트·선택 기능 | 좌표, 경계 도형, 자치구 코드, 날짜별 생활인구 제공 | E·F가 지도·차트·랭킹·대시보드·선택 인터랙션 구현 |

자치구 매핑은 B가 구현 책임을 갖고 C가 지원합니다. 최종 전달 데이터에 배정 결과와 처리 상태를 담아 동일한 매핑을 각 파트에서 다시 구현하지 않도록 합니다. 면적 단위 정리와 공간 매핑은 전처리이며, 밀도·점수·순위 계산은 D의 책임입니다.

## 객체지향 설계

`DataLoader` 객체가 입력 설정, 원본, 정제 결과, 병합 결과를 관리하고 자신의 메서드로 상태를 변경합니다. A와 B는 같은 클래스의 서로 다른 메서드를 담당합니다.

### 속성

| 속성 | 내용 |
| --- | --- |
| `_data_dir` | 입력 파일이 있는 프로젝트 내부 경로 |
| `_raw_data` | 원본을 읽고 컬럼명을 통일한 데이터 묶음 |
| `_cleaned_data` | 정제된 데이터 묶음 |
| `_prepared_data` | 자치구 연결을 마친 최종 데이터 묶음 |
| `_metadata` | 출처, 기준시점, 인코딩, 좌표계, 처리 기준 |
| `_quality_report` | 제외·중복·결측·매핑 실패 건수와 사유 |

속성 이름 앞의 `_`는 내부 관리용이라는 약속입니다. 호출자는 원본이나 내부 상태를 직접 변경하지 않고 공개 메서드를 사용합니다. 원본·정제 결과는 별도 객체로 보관하고, 결과를 반환할 때도 내부 데이터를 외부에서 변경하지 않도록 복사본을 제공합니다.

### 공개 메서드

| 메서드 | 담당 | 역할 | 반환 |
| --- | --- | --- | --- |
| `load_data()` | A | 파일 읽기, 필수 컬럼 검사, 표준 컬럼명 적용, 원본·메타데이터 저장 | 없음 |
| `clean_data()` | B | `_raw_data`의 복사본을 정제하여 `_cleaned_data`에 저장 | 없음 |
| `merge_data()` | B | 정제된 정류장·생활인구를 자치구에 연결하고 결과·검증 정보 저장 | 없음 |
| `get_data()` | B, A와 형식 합의 | 최종 데이터 묶음의 복사본 제공 | 데이터 묶음 |

- `load_data()` 전에 `clean_data()`를 호출하거나 정제 전에 `merge_data()`를 호출하면 실행 순서를 설명하는 오류를 냅니다.
- `get_data()`는 병합 완료 후에만 사용할 수 있습니다.
- 파일을 다시 읽으면 이전 정제·병합 결과를 초기화합니다. 정제를 다시 하면 이전 병합 결과를 초기화합니다.
- 같은 입력으로 다시 실행할 때 행이나 처리 이력이 계속 누적되지 않도록 합니다.
- 파일 읽기·정제·매핑의 세부 작업은 `_read_bus_stops()`, `_clean_living_population()`, `_assign_districts()` 같은 내부 보조 메서드로 나눕니다.

### 객체 사용 흐름

다음은 위 인터페이스에 따른 호출 예시입니다.

```python
from pathlib import Path
from src.data_loader import DataLoader

project_dir = Path(__file__).resolve().parent
loader = DataLoader(data_dir=project_dir / "data" / "raw")

loader.load_data()       # A: 파일 읽기
loader.clean_data()      # B: 정제
loader.merge_data()      # B: 자치구 연결
prepared = loader.get_data()

bus_stops = prepared["bus_stops"]
districts = prepared["districts"]
living_population = prepared["living_population"]
```

호출 코드는 파일 인코딩, 결측치 처리, 공간 매핑의 내부 절차를 몰라도 데이터를 사용할 수 있습니다. 객체지향 적용은 **상태와 동작의 캡슐화, 명확한 클래스 책임, 공개 메서드를 통한 협력**으로 드러냅니다. 상속은 실제 공통 동작과 대체 가능한 하위 타입이 필요한 경우에만 도입합니다.

### 생활인구 컬럼

`250m`는 기초 공간 단위이며 이 파일은 이미 자치구별로 집계되어 있습니다. 격자를 다시 합산하지 않습니다.

| 원본 | 표준 컬럼 | 자료형·의미 |

| `기준일ID` | `reference_date` | 날짜 |
| `시구코드` | `district_code` | 5자리 문자열 |
| `시구명` | `district_name` | 문자열 |
| `총생활인구수` | `living_population` | 실수, 기본 인구 지표 입력 |
| `주간인구수(09~18)` | `daytime_population` | 실수 |
| `야간인구수(19~08)` | `nighttime_population` | 실수 |
| `내국인생활인구수` | `domestic_population` | 실수 |
| `장기체류외국인인구수` | `long_term_foreign_population` | 실수 |
| `단기체류외국인인구수` | `short_term_foreign_population` | 실수 |
| `일최대인구수` | `max_population` | 실수 |
| `일최소인구수` | `min_population` | 실수 |
| `서울외유입인구수` | `inflow_population` | 실수 |
| `자치구간이동인구수` | `interdistrict_movement_population` | 실수 |
| `적재일시` | `loaded_date` | 날짜, 기준일과 구분 |
| `요일` | `day_of_week` | 문자열 |

기온·강수량 컬럼은 원본에 보존합니다. 해당 컬럼의 결측치 때문에 생활인구 행 전체를 삭제하지 않습니다. 총생활인구에 내국인·외국인 값을 다시 더하지 않습니다.

- 기준일 범위는 2023-01-01 ~ 2026-10-04로 총 1,372일입니다.
- 날짜마다 서울시 전체 1행과 자치구 25행이 있습니다.
- `시구코드 == "11000"`인 서울시 전체 행을 제외하면 34,300행입니다.
- `기준일ID + 시구코드` 중복은 없으며 기본 사용 컬럼에는 빈 값이 없습니다.

정제 결과에서도 **전체 날짜를 보존**합니다. 날짜 선택과 기간 평균·주야간 지표 사용 기준은 후속 분석에서 정하며, A·B가 임의로 한 날짜나 평균값만 남기지 않습니다.

### 자치구 경계 및 면적

두 CSV에는 자치구 경계와 면적이 없으므로 A가 별도 공간 파일을 확보해야 합니다. 지도와 정류장 매핑에 필수인 입력입니다.

- 자치구 코드·자치구명·경계 도형과 원본 좌표계를 확인합니다.
- 생활인구의 5자리 자치구 코드와 체계가 다르면 B가 검증된 변환표로 통일합니다.
- 면적은 출처가 확인된 값을 우선 사용합니다. 경계에서 산출하면 적절한 투영좌표계로 계산하고 방법·좌표계·단위를 기록합니다.
- 경계의 기준시점과 정류장·생활인구의 시점 차이를 기록합니다.

## B의 정제·매핑 기준

### clean_data()

- 식별자는 문자열, 인구·좌표·면적은 숫자, 기준일은 날짜로 변환합니다.
- 원본 좌표계를 확인하고 정류장·경계를 같은 좌표계로 변환합니다. 파일 값이 경도·위도 형태라는 이유만으로 원본 좌표계를 확정하지 않습니다.
- 동일 식별자의 완전히 같은 중복은 기록 후 제거하고, 값이 충돌하는 중복은 별도로 분리합니다.
- 생활인구 중복 키는 `reference_date + district_code`입니다.
- 결측 생활인구와 실제 0을 구분합니다. 결측을 0으로 대체하거나 주변 날짜로 임의 보간하지 않습니다.
- 음수 생활인구, 유효하지 않은 좌표, 빈 경계·잘못된 도형, 0 이하 면적을 검출합니다. 자동 보정 시 원본과 보정 사유를 보존합니다.
- 분석 제외·오류 행은 원본 식별자와 사유를 남깁니다.

### merge_data()

1. 유효한 정류장 좌표와 자치구 경계를 공간 매핑합니다.
2. 단일 자치구가 확인된 정류장에 `district_code`를 부여합니다.
3. 경계선 위 정류장, 미배정, 다중 매칭은 C와 공유할 검토 목록에 남깁니다. 임의로 첫 번째 구나 가장 가까운 구에 배정하지 않습니다.
4. 자치구 기본 목록을 기준으로 날짜별 생활인구를 연결합니다. 누락된 날짜·자치구 조합은 결측 및 상태로 표시합니다.
5. 정류장 표, 자치구 공간 데이터, 날짜별 생활인구 표를 공통 `district_code`로 연결 가능한 별도 결과로 제공합니다.

생활인구의 모든 날짜를 정류장 표에 직접 붙여 정류장 행을 늘리지 않습니다. 정류장 매핑 실패가 남으면 해당 건수와 영향 여부를 함께 전달하여 후속 집계를 완전한 결과로 오해하지 않도록 합니다.

## 최종 데이터 전달 계약

`get_data()`는 아래 키를 갖는 데이터 묶음을 반환합니다.

| 키 | 형식 | 단위·내용 |
| --- | --- | --- |
| `bus_stops` | pandas DataFrame | 정류장 1개당 1행. 분석 대상이며 단일 자치구 매핑이 완료된 정류장 |
| `districts` | GeoPandas GeoDataFrame | 자치구 1개당 1행. 서울 25개 자치구 기본 목록·면적·경계 |
| `living_population` | pandas DataFrame | 기준일 × 자치구당 1행. 전체 날짜 및 누락 상태 보존 |
| `issues` | pandas DataFrame | 제외·오류·검토 대상의 원본 키, 처리 단계, 사유, 후보 자치구 등 |
| `metadata` | dict | 출처·기준시점·단위·좌표계·처리 조건·스키마 버전 |
| `quality_report` | dict | 입력·출력·제외·실패 건수, 완전성 검사 결과 |

### 필수 필드

- `bus_stops`: `stop_id`, `source_node_id`, `stop_name`, `longitude`, `latitude`, `stop_type`, `district_code`
- `districts`: `district_code`, `district_name`, `area_km2`, `geometry`
- `living_population`: 위 생활인구 표의 표준 컬럼과 `data_status` (`valid`, `missing`, `invalid`)
- `issues`: `source_dataset`, `source_key`, `stage`, `reason`, `action`. 생활인구는 날짜와 자치구를 함께 원본 키로 사용합니다.

출력 좌표는 원본 좌표계 확인 후 WGS84 경도·위도로 변환하고, 공간 객체의 CRS와 메타데이터에 명시합니다. 면적 계산용 좌표계는 별도로 기록합니다. 경계 도형은 E가 지도를 그릴 수 있도록 원형을 보존하고 화면용 단순화는 수행하지 않습니다.

`data_status=valid`는 기본 생활인구 값이 유효하다는 의미입니다. 주간·야간 등 보조 필드의 결측·이상은 필드별로 기록하며 0으로 바꾸지 않습니다.

C는 `stop_id`로 정류장 객체를 만들고 `district_code`로 구역에 연결할 수 있습니다. D는 같은 코드와 선택 날짜로 생활인구·면적을 가져올 수 있고, E·F는 같은 코드로 경계·좌표·날짜별 값을 연결할 수 있습니다. `District`의 속성 이름과 단위는 C·D와 합의하되 원본 생활인구의 의미를 유지합니다.

### 저장 형식

| 파일 | 내용 |
| --- | --- |
| `bus_stops.csv` | 정제·매핑된 정류장 |
| `living_population.csv` | 날짜별 자치구 생활인구 |
| `districts.geojson` | 경계·면적·자치구 기본 정보 |
| `issues.csv` | 제외·오류·검토 대상 |
| `metadata.json` | 자료·스키마·처리 기준 정보 |
| `quality_report.json` | 검증 결과 |

출력 CSV는 UTF-8 BOM(`utf-8-sig`), 날짜는 `YYYY-MM-DD`, 결측 숫자는 빈 값으로 저장합니다. CSV에는 자료형 정보가 없으므로 읽는 쪽에서도 식별자를 문자열로 지정합니다. 메모리 반환과 파일 출력의 컬럼·단위·결측 의미를 동일하게 유지합니다.

`metadata`에는 정류장 기준시점, 생활인구 기간, 경계 기준시점, 다운로드 날짜, 실행 시각, 면적 출처, 필터 조건을 기록합니다. 확인하지 못한 기준시점은 미확인으로 남기고 다운로드 날짜로 대신하지 않습니다.

## 전달 전 검증

- 정류장 식별자가 유일하고, 최종 정류장마다 자치구가 하나만 배정되어 있는가?
- 입력 정류장 수가 전달·분석 제외·오류·중복 제거 건수로 설명되는가? 건수 집계는 중복되지 않는 처리 분류를 사용하는가?
- 25개 자치구 코드가 유일하고 경계·면적이 유효한가?
- 모든 정류장·생활인구 코드가 자치구 목록에 존재하는가?
- 생활인구의 날짜·자치구 중복이 없고, 날짜별 25개 구의 누락 여부가 기록되는가?
- 전체 날짜, 주간·야간 값, 지도용 경계가 보존되어 있는가?
- 원본·출력 시점, 좌표계, 면적 단위, 제외 기준과 검토 대상이 전달되는가?

필수 파일·컬럼 누락이나 경계 코드 충돌은 전달을 중단하는 오류로 처리합니다. 개별 값의 결측·매핑 실패는 검토 목록과 품질 보고서에 남기고, 완전성 상태를 표시합니다. 단순히 파일이 생성되었다는 이유로 검증 성공으로 표시하지 않습니다.

## 실행 방법

`main.py`는 `DataLoader`의 공개 메서드를 순서대로 호출하고 반환 데이터를 저장하는 진입점입니다. 명령은 저장소 최상위 폴더에서 실행합니다.

### 1. 가상환경과 패키지 설치

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

macOS / Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

### 2. 입력 파일 확인

`data/raw/`의 두 CSV와 자치구 경계 파일을 확인합니다. 경계 파일은 별도로 확보해야 합니다. 경로는 개인 PC의 다운로드 폴더가 아닌 프로젝트 폴더를 기준으로 사용합니다.

### 3. 실행

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe main.py
```

macOS / Linux:

```bash
.venv/bin/python main.py
```

실행 순서는 `load_data()` → `clean_data()` → `merge_data()` → `get_data()`이며 결과는 `data/processed/`에 저장합니다. 처리 로그와 `quality_report.json`, `issues.csv`를 확인한 뒤 데이터 버전을 공유합니다.
